# 积分与手写作答

## 使用规则

- 新注册账号赠送100积分，可提交10套真题。每次整卷提交扣10积分，申论及面试真题适用，题数不同仍按整套计费。
- 只有填写完整并成功创建作答记录时扣费；保存草稿、OCR识别、查看报告和原记录重新批改不额外扣费。重新作答并创建新记录会重新扣费。
- 不足10积分返回402并保留答案。失败批改可从原记录重试，无需新建提交。
- 旧账号迁移时余额为0，不改写已有作答。管理员从“用户与权益 / 调整积分”增加或扣减积分，必须填写原因；用户详情展示最近50笔账本及操作人。
- 右上角展示当前余额，进入页面、页面切换、重新聚焦窗口和提交后刷新。
- 当前没有支付、充值或套餐交易。后台调分是人工额度管理。

## 数据一致性

`users.credits` 保存整数余额，`credit_ledger` 保存不可通过业务接口编辑或删除的变动明细。用户行锁串行处理同一用户的调分和扣费；余额、账本、整卷及各题作答在同一MySQL事务内写入。余额不可为负，最高1000000积分。

整卷提交要求16—80位字母数字或连字符的 `requestId`，浏览器会将重试标识与答案一起保存在当前账号的本地提交缓存中。`(user_id, request_key)` 唯一约束阻止重复扣费，答案摘要阻止同一个标识提交不同内容。返回丢失后重试原请求会返回原记录。

旧 `/api/scoring/evaluate` 没有用户端调用，现仅保留管理员内部评分调试权限，普通用户统一从真题整卷接口提交，不能经旧接口绕过扣费。

## 手写识别

使用开源 [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) 的 [PP-OCRv5 中文手写模型](https://github.com/PaddlePaddle/PaddleOCR/blob/release/3.3/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5.en.md)。依赖固定为 PaddleOCR 3.3.3 / PaddlePaddle 3.2.2，采用轻量 mobile_det 检测与高精度 server_rec 识别组合在CPU运行，模型初始化和预测复用同一个专用线程，限制原生线程与内存分配区；该模型明确支持中文手写，字迹潦草、反光、模糊或表格线干扰仍可能错字。

答题区点击“手写上传” → 选择照片 → 识别文字 → 对照原图校对 → 追加或替换本题答案。编辑器支持文字修改、合并单行换行、空行分段和段落上下移动；低置信度行会提示复核。多张照片可逐张识别并追加。

原图只在浏览器预览和服务内存中使用，不上传OSS或保存到公开目录；关闭组件释放预览。识别草稿仅在当前对话框实例中暂存，刷新或切题前应填入答案并保存。系统不会直接把识别内容当成最终答案自动提交。

上传要求登录，单张8MB以内，支持JPG、PNG、WebP；后端核验文件头，OCR端解码检查并限制2000万像素，识别前按比例缩小长边至2600像素。每个用户每分钟最多6次上传，查询进度不计入该次数。

OCR采用先来先服务的异步队列：1项执行、最多20人等待，每个账号最多一项未结束任务。页面每2秒查询一次，展示前方等待人数、正在识别人数及预计开始等待时间（不包含本人的识别耗时），轮到后自动识别。初始单图估算15秒，后续用实际耗时的加权平均动态更新；预计时间不是承诺。

接口：`POST /api/handwriting/jobs` 上传并返回202及任务ID；`GET /api/handwriting/jobs/:id` 查询自己的排队/运行/完成/失败状态；`DELETE /api/handwriting/jobs/:id` 取消。越权查看或取消均返回404。旧同步上传接口保留兼容，并使用同一队列。

取消或关闭窗口释放等待位置；运行中的原生推理不能中断，会完成后丢弃结果。等待任务超过90秒未查询自动取消，结果最多暂存5分钟且只保留最近100项。照片只在内存排队，不落盘、不上传OSS；队列满返回明确提示。队列依赖当前单个Node进程，服务重启会清空任务，页面提示重新识别，已填入答案保留；扩展多实例前必须改用共享队列。网络轮询连续失败会提示重试并尝试取消，单项识别失败不会阻塞后续任务。

## 部署

先按部署文档备份应用和数据库，在 `backend` 工作目录执行：

```bash
node src/seeds/migrate-credits.js
```

迁移幂等，只增量添加余额列和账本表。普通 `sequelize.sync()` 不替代旧库迁移。

独立Docker服务目录 `ai-service/ocr`：

```bash
docker build -t policyquest-ocr:20260908 ai-service/ocr
# /opt/policyquest/ocr.env 中设置独立随机 OCR_SERVICE_TOKEN，文件权限600。
docker run -d --name policyquest-ocr --restart unless-stopped \
  --cpus=2 --memory=3g --pids-limit=256 \
  -p 127.0.0.1:8091:8091 --env-file /opt/policyquest/ocr.env \
  -v /opt/policyquest/ocr-models:/root/.paddlex \
  policyquest-ocr:20260908
```

后端 `.env` 设置 `OCR_SERVICE_URL=http://127.0.0.1:8091` 和与OCR服务一致的 `OCR_SERVICE_TOKEN`，重启本项目PM2进程。首次启动自动下载模型，须待 `/health` 返回 `ready:true` 后再验收。服务端口只绑定回环地址，不公开暴露；无需付费OCR密钥。

Nginx的PolicyQuest API location需设置 `client_max_body_size 10m` 与至少150秒读取超时；只改该location，不影响其他应用。大图仍受应用8MB限制。

回滚时恢复本次应用与Nginx备份，仅重启PolicyQuest，保留新增积分列和账本，避免丢失上线后作答与额度记录。OCR容器可单独停止；不要恢复旧数据库覆盖新数据。
