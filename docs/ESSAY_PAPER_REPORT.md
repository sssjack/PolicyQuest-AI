# 申论整卷能力诊断

每套申论题组提交后先逐题评分，全部完成后自动生成独立的整卷报告。按实际题数、原题满分汇总，支持2题、4题、5题等不同题组。生成过程中和失败时保留单题成绩；仅重新生成总结不会重新评分。

## 使用入口

- 提交申论后进入 `/paper-report/:attemptId`，自动刷新单题和整卷生成状态。
- 练习历史中的申论记录进入整卷诊断；成绩表和每题复盘可跳到对应单题批改。
- 学习报告页增加整卷能力档案和最近五套记录。
- 历史新版申论记录首次打开时可补生成；旧百分制报告需先按原题满分重新批改，不能直接换算后冒充整卷诊断。

## 两阶段处理

1. 程序核验全部单题为 `essay-v2` 且已批改，校验分数范围和各维度合计，提取题型、分项、材料采点、字数、用时、去重诊断和训练建议，保存结构化中间结果。
2. `gpt-5.6-luna` 根据结构化单题诊断生成总评、跨题共性、优势保留建议、每题复盘、最多三项优先级和七天计划。该阶段不接收完整原始试卷和答案，不重新评分。题号、能力id、错误标签、证据id和每日任务结构均校验。

单题重批会使旧整卷报告及生成令牌失效，旧任务不能覆盖新结果。重复生成通过数据库状态原子领取；服务重启将中断的总结标记为可重试。当前部署采用单实例进程，非跨机器持久队列。

## 十个页面模块

成绩总览、十维能力画像、跨题共性问题、本套优势、每题一句话复盘、错误标签与变化、提分优先级、目标分差、七天训练计划、个人申论档案。总分区显示本套得分、等级、水平判断、核心短板及AI总评。

能力维度为材料理解、要点提取、归纳分类、概括表达、对策能力、应用文能力、文章立意、论证能力、结构组织、语言表达。分数按相关单题分项的满分加权折算为10分；对策、应用文、作文专项仅引用对应题型。未考查项显示“未考查”并从雷达图排除，避免误画成零分。展开“评分依据”可查看引用的题号、分项、得分和原诊断理由。这是关联能力观察量表，并非十个独立的官方评分指标。

能力类型由本套分数和相对优势确定，包括材料型、表达型、逻辑型、作文型、基础巩固型、高分冲刺型、均衡发展型。它是学习提示，不是固定人格判断。总得分率85%以上为A，75%以上为B+，65%以上为B，60%以上为C+，其余为C，均为教学分级。

## 数据口径

- 共性问题要求同一标签出现在至少两题，最多突出三个。次数按“题号＋标签＋原文＋问题”去重后的诊断条目计，不等于扣分次数。展开后能看到真实原句、改写及原因。
- 历史档案读取最近30套已完成记录，筛选其中最近10套完整新版申论报告；同一练习重批只算一套。趋势比较前后两组每套均值，少于4套或相应指标无样本时显示样本不足。不同题组难度未校准，比较时展示原始得分和得分率。
- 小题踩点率、遗漏率不混入大作文的立意参考点；作答速度用有效记录的字数与用时计算，缺用时不生成速度。
- 目标分按每套实际满分保存，默认满分的75%，可自行修改。分差为目标减当前分，达到目标后归零。
- 下一轮练习预算为各题剩余失分的35%，逐题不超过满分；是透明的训练目标，不是AI预测或成绩承诺。优先项可能涉及同一题，其预算不能相加。
- 不编造“超过XX%考生”、统计排名或历史成绩。参考答案与教学评分的局限继续适用。

## 接口与存储

接口均要求登录并校验记录属于当前用户：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/real-papers/attempts/:id/paper-report` | 报告状态、中间数据、AI总结、目标和截至本次提交的趋势 |
| POST | `/api/real-papers/attempts/:id/paper-report` | 首次补生成或只重试失败总结；成功报告不重复生成 |
| PUT | `/api/real-papers/attempts/:id/paper-target` | 保存数字字段`target`，范围为0至本卷满分 |
| GET | `/api/real-papers/paper-profile` | 当前用户最近整卷记录及标签趋势 |

`real_paper_attempts`新增`paper_report` JSON、`paper_report_status`、`paper_report_error`、`paper_report_token`和`target_score`。迁移命令：`node src/seeds/migrate-paper-report.js`，重复执行不会重复加列。发布与备份见根目录部署文档。
