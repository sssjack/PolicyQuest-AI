# 手机号注册与验证码改密

登录、注册和找回密码沿用PolicyQuest学习中心的蓝色PQ标识、浅蓝灰背景、白色卡片与蓝色按钮，直接复用全站颜色、圆角和字体变量。保持简约留白，以学习进步曲线作轻量装饰。注册仅需大陆手机号、短信验证码和密码；老用户名和邮箱登录保持兼容。

## 用户流程

登录或注册成功后统一进入学习中心`/coach`，不恢复登录前的真题、历史或其他目标页；旧登录链接中的`redirect`参数也不再影响落地页。

- 注册：获取短信验证码 → 输入6位验证码和8–64位密码 → 创建账号、赠送100积分并登录。验证码通过后才能注册；不再开放邮箱直接注册。多字节密码另受bcrypt的72字节上限约束。
- 忘记／修改密码：在登录页“忘记密码”或个人信息“账号安全”进入；验证已绑定手机号，设置新密码。成功后所有旧登录令牌立即失效，需要重新登录。
- 老账号：个人信息 → 账号安全 → 输入当前密码和待绑定手机号 → 接收并核验验证码。绑定保留原账号、作答、角色和积分，不再赠送注册积分。已绑定号码不支持直接换绑。
- 联系邮箱为选填项，不再作为注册必填条件；后台用户管理支持按手机号搜索。

## 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/auth/sms-code` | `{phone,purpose:register/reset}` 发送验证码 |
| `POST /api/auth/register` | `{phone,code,password}` 验证并注册 |
| `POST /api/auth/reset-password` | `{phone,code,password}` 验证并改密 |
| `POST /api/auth/phone/code` | 登录后以当前密码确认身份，发送绑定验证码 |
| `POST /api/auth/phone` | 登录后提交当前密码、手机号和验证码完成绑定 |

手机号唯一，邮箱允许NULL。服务器自动生成内部用户名，昵称默认“同学+手机号后四位”。旧令牌未带`tv`时视为版本0，只有改密才递增`users.token_version`。

## 短信与核验

沿用PixelForge已配置的阿里云号码认证服务`Dypnsapi SendSmsVerifyCode`，独立调用官方Node SDK（2.0.0），不是短信服务Dysmsapi；签名、模板与AccessKey只保存在服务端环境配置，不输出到页面、文档或日志。未设置生产模拟验证码模式。官方接口说明：https://help.aliyun.com/zh/pnvs/developer-reference/api-dypnsapi-2017-05-25-sendsmsverifycode

- 验证码为安全随机6位数字，有效5分钟，60秒重发间隔。
- 每手机号每天最多10次发送尝试，全站默认500次（`SMS_DAILY_LIMIT`）；IP每15分钟最多8次发送、20次验证码提交。登录失败每IP15分钟最多30次。发送与校验还有应用通用限流。
- 数据库只保存带密钥的验证码摘要；用途和绑定账号隔离，错5次作废，新验证码覆盖旧验证码。核验、消费验证码与注册／改密／绑定在同一MySQL事务内完成，核验失败次数单独提交，避免回滚绕过限制。
- 发送失败、超时不会启用该验证码，不自动重发以免重复扣费。短信使用阿里云现有短信认证额度/计费，网站训练积分不因短信发送扣减。
- 未注册或禁用手机号的重置请求返回统一提示，不泄露账号状态。验证码不写入响应或日志。

## 部署和回滚

先备份应用、环境配置和数据库，安装固定依赖，再执行`node src/seeds/migrate-phone-auth.js`。迁移幂等，新增`phone`唯一列、`token_version`列、`sms_challenges`与`sms_quotas`，邮箱改为可空。旧密码、积分与作答保持原值。

设置`ALIYUN_SMS_ACCESS_KEY_ID`、`ALIYUN_SMS_ACCESS_KEY_SECRET`、`ALIYUN_SMS_SIGN_NAME`、`ALIYUN_SMS_TEMPLATE_CODE`、`ALIYUN_SMS_TEMPLATE_PARAM_NAME`和可选`ALIYUN_SMS_TEMPLATE_MIN_PARAM_NAME`。SMS SDK连接超时5秒、读取超时10秒，通过HTTPS调用阿里云。

发布前确认没有正在批改和生成中的AI任务，再重启PolicyQuest后端并更新前端入口。回滚应用时保留新增手机号和验证码表，不用旧数据库覆盖上线后账户数据；已注册手机号账户需要保留新版登录逻辑，不能盲目退回仅用户名/邮箱的登录实现。

本地36项真实MySQL隔离测试通过，覆盖幂等迁移、历史重复索引合并、并发注册、验证码用途与时效、重放与错误次数、改密后令牌失效、老账户兼容及绑定。四种屏幕宽度（1440、768、390、360）验证登录/注册/重置三个页面及短信倒计时、显示密码和确认密码交互。测试文件仅保存在本地忽略目录。线上向用户指定手机号发送1条真实注册验证码，API成功，用户已确认收到；未用该验证码创建或修改用户账号。
